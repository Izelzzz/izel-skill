# 产品设计哲学

原则审查回答「是否应当做」。本 skill 回答「应做成何种形态，方可被理解、被信任并持续使用」。适用于方向已定、需打磨体验与表达，或需审查方案是否过重、是否过度承诺、首次使用路径是否清晰的情形。原则审查尚未通过时，应先完成原则审查。

共四项方法。按场景选用；不适用项应跳过并说明理由。已跳过的项，不得在事后视为已满足。

**少即是多。** 判断用户完成主任务需理解的概念数量。检查主路径中的概念、文案、步骤与选项能否减少，且不损害必要能力。若概念堆叠导致理解成本过高，判定未满足，并列出可删除或可合并项。

**长期信任。** 判断设计是在积累信任与长期收益（如留存、可信度、可复用数据能力），还是以透支信任换取短期刺激。若属透支或一次性噱头，判定未满足，并说明如何改为可积累的设计。

**控制预期。** 判断对外表述是否不超过真实能力，真实问题是否表述清楚。承诺须可兑现、可核验。若存在空洞叙事或过度承诺，判定未满足，并改为可核对的表述。

**叙事与 onboarding。** 判断新用户能否在较短路径内理解产品为其解决的问题，以及价值、场景与下一步是否清晰。若叙事与产品能力脱节，判定未满足，并给出文案或路径的具体修改。

先确认场景：新产品或增量功能、是否存在首次接触路径、是否为内部工具、是否涉及支付或隐私等信任敏感场景。新产品或新功能首次对外时，通常启用少即是多、控制预期与叙事；成熟产品增量通常启用少即是多与控制预期，若无新用户路径可跳过叙事；内部工具通常启用少即是多与控制预期，叙事常可跳过；信任敏感场景须启用长期信任与控制预期。上述为默认指引，可以调整，但须写明理由。

对每个启用的方法，仅以「满足 / 未满足」判定，并附证据。未满足项须给出可执行修改，不得直接批准体验定稿。全部启用项满足后，方可进入规格或实现细化。不得以模糊的「优先级」替代判断；若需安排修改顺序，应先处理导致未满足的缺口，并直接写明修改内容。

输出应包含：场景说明、启用与跳过项及其理由、各启用项的判定与修改意见、总体结论（可继续 / 需修改）。场景不清晰时，先补充上下文再审查。
