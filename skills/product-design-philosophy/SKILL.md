# 产品设计哲学

## 何时使用

在以下情况 SHOULD 使用本 skill：

- 方案方向已定，需要打磨体验与表达
- 评审「是否做得过重 / 是否过度承诺 / onboarding 是否说清」
- 新产品或新功能需要叙事与预期管理

原则闸门（product-design-principles）未过时，MUST 先过原则，再跑哲学。

开始时宣布：正在使用 product-design-philosophy 做选择性哲学检查。

## 四条哲学（按需选用）

| ID | 名称 | 含义 |
|----|------|------|
| P1 | 少即是多 | 减少噪音，降低理解成本 |
| P2 | 长期主义 | 逐步建立信任，不做一次性爆款逻辑 |
| P3 | 控制预期 | 不夸大能力；解决真问题优先于宏大叙事 |
| P4 | 叙事艺术 | 优秀 onboarding = 优秀叙事；用户应快速感到「产品懂我」 |

## Step 1 — 判断上下文

记录：

- 场景：新功能 / 新产品 / 改版 / 内部工具 / B2B / 消费级
- 规模：MVP / 增长期 / 成熟期
- 用户认知成本：高 / 中 / 低
- 是否有首次接触（onboarding）路径

## Step 2 — 选择适用哲学

按表选择。不适用则跳过，并写一句理由。

| 上下文 | 默认启用 | 可跳过 |
|--------|----------|--------|
| 新产品 / 新功能首次曝光 | P1, P3, P4 | P2 若纯实验且明确短期 |
| 成熟产品增量功能 | P1, P3 | P4 若无新用户路径；P2 按战略 |
| 内部工具 | P1, P3 | P4 常可跳过；P2 视组织目标 |
| 营销向改版 | P3 MUST | P1/P4 视噪音与首次路径 |
| 信任敏感（支付、隐私、医疗等） | P2, P3 MUST | — |

规则：

- MUST 写清「启用哪些 / 跳过哪些 / 为什么」。
- 信任敏感场景 MUST NOT 跳过 P2 与 P3。

## Step 3 — 逐项打分

对每个**启用**的哲学打 1–5 分（5 最好），并给一条证据。

### P1 少即是多

问：用户要理解几件事才能完成主任务？能否删掉概念、文案、步骤或选项而不损能力？

- 5：主路径概念极少，噪音已砍
- 3：可用但有可删噪音
- 1：概念堆叠，理解成本高

### P2 长期主义

问：此设计是否在积累信任与复利，还是只追求一次性刺激？

- 5：明确复利机制（留存、信任、数据飞轮等）
- 3：中性
- 1：透支信任或一次性噱头

### P3 控制预期

问：对外说法是否不超过真实能力？是否把真问题解决写清楚？

- 5：承诺可验证且可兑现
- 3：略满但可纠正
- 1：过度承诺或空叙事

### P4 叙事艺术

问：新用户能否在短路径内感到「懂我」？onboarding 是否讲清价值、场景、下一步？

- 5：叙事短、准、可感知
- 3：能用但慢热
- 1：无叙事或叙事与产品脱节

## Step 4 — 输出与行动

输出模板：

```
【哲学选择】
上下文：
启用：
跳过 + 理由：

【评分】
P1 … 分 | 证据 | 行动
P2 … 分 | 证据 | 行动
P3 … 分 | 证据 | 行动
P4 … 分 | 证据 | 行动

【总判】
保留 / 需改 / 暂缓
优先改动（最多 3 条）：
```

行动规则：

- 任一启用项 ≤ 2 分 → MUST 给出具体改动，不得直接批准体验定稿。
- 启用项均 ≥ 4 → 可进入规格或实现细化。
- 跳过项 MUST NOT 事后当作已满足。

## 完成标准

- 有明确启用/跳过表
- 启用项均有分数与证据
- 低分项有可执行改动

## 停止条件

- 原则闸门未过 → 退回 product-design-principles
- 上下文信息不足 → 先补场景与规模，再评分
