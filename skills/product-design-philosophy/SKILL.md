# 产品设计哲学

## 使用时机

当原则检查已经通过，且任务需要打磨体验、表达、首次使用路径或长期信任时，使用本 skill：

- 新产品或新功能需要明确价值表达。
- 方案需要减少理解成本。
- onboarding、营销文案或首次使用路径需要评审。
- 产品处于信任敏感场景。

开始时写明：`正在使用 product-design-philosophy 进行选择与评分。`

## 前置条件

读取 product-design-principles 的结果。原则检查存在未认领缺口时，先处理缺口。没有场景、规模或首次使用信息时，输出缺口并停止评分。

## 执行流程

### 1. 记录上下文

写明：

- 场景：新产品、新功能、改版、内部工具、B2B 或消费产品。
- 阶段：MVP、增长期或成熟期。
- 用户理解成本：高、中或低。
- 是否有首次使用路径。
- 是否涉及支付、隐私、医疗或其他信任敏感内容。

### 2. 选择检查项

检查项如下：

- **P1 少即是多**：减少概念、步骤、文案和选项，让用户更快完成主任务。
- **P2 长期主义**：持续积累信任、留存、数据价值或使用习惯。
- **P3 控制预期**：承诺与实际能力一致，并把真实问题说清楚。
- **P4 叙事艺术**：让用户在短路径内理解价值、场景和下一步。

默认选择规则：

- 新产品或首次曝光：启用 P1、P3、P4。短期实验可跳过 P2，但要说明原因。
- 成熟产品增量功能：启用 P1、P3。P4 取决于是否新增用户路径，P2 取决于长期目标。
- 内部工具：启用 P1、P3。P4 取决于首次使用路径，P2 取决于组织目标。
- 营销改版：P3 必须启用。P1、P4 根据信息噪音和首次路径选择。
- 信任敏感场景：P2、P3 必须启用。

输出：

```text
【哲学选择】
上下文：
启用：
跳过：
跳过理由：
```

### 3. 逐项评分

每个启用项使用 1 到 5 分，并写证据与动作。

- 5 分：证据充分，用户可直接感知价值。
- 3 分：基本可用，仍有可改善内容。
- 1 分：严重影响理解、信任或完成任务。

评分问题：

- P1：用户需要理解多少概念才能完成主任务？还能移除哪些内容？
- P2：当前设计是否积累长期价值？是否透支未来信任？
- P3：每项对外承诺能否被当前能力验证？
- P4：用户能否快速理解价值、适用场景和下一步？

输出：

```text
【评分】
P1 少即是多：分数 / 证据 / 改动
P2 长期主义：分数 / 证据 / 改动
P3 控制预期：分数 / 证据 / 改动
P4 叙事艺术：分数 / 证据 / 改动
```

### 4. 生成行动

- 任一启用项为 1 或 2 分时，必须给出具体改动，不能批准当前体验定稿。
- 启用项全部达到 4 分或 5 分时，允许进入 product-spec 或实现细化。
- 跳过项保持为“未检查”，不能在结论中当作通过。
- 改动最多列 3 条。每条改动写负责人、完成条件和验证方式。

输出：

```text
【行动】
状态：保留 / 需要修改 / 暂缓
优先改动：
1. 改动内容 / 负责人 / 完成条件 / 验证方式
2. 改动内容 / 负责人 / 完成条件 / 验证方式
3. 改动内容 / 负责人 / 完成条件 / 验证方式
```

## 完成标准

- 上下文信息完整。
- 每个检查项都有启用或跳过决定。
- 每个启用项都有分数、证据和行动。
- 低分项都有可验证的改动。
- 最终状态符合评分规则。

## 停止条件

原则检查未通过时，退回 product-design-principles。上下文信息不足时，输出缺口，不进行主观评分。
