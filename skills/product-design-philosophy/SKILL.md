# 产品设计哲学

原则回答「该不该做」。哲学回答「做成什么样才让人愿意用、愿意信」。

这四条不是每次全开。按场景选，用不上就跳过，并说一句为什么。

## 何时用

- 方向已定，要打磨体验与表达
- 在问：是不是太重、是不是过度承诺、onboarding 说没说清
- 新产品或新功能第一次见用户

原则闸门还没过，先回去过原则。哲学救不了错误的问题。

## 四条方法

| 代号 | 名称 | 核心问题 |
|------|------|----------|
| P1 | 少即是多 | 用户要理解几件事才能完成主任务？能少一点吗？ |
| P2 | 长期信任 | 这是在积累信任，还是在透支信任换一次刺激？ |
| P3 | 控制预期 | 对外说法有没有超过真实能力？真问题写清楚了吗？ |
| P4 | 叙事 / onboarding | 新用户能不能很快感到「这东西懂我」？ |

## 怎么选

先看上下文：新功能还是新产品？MVP 还是成熟期？B2B 还是消费级？有没有首次接触路径？信任敏不敏感（支付、隐私、医疗等）？

默认启发（可改，改了要说理由）：

- **新产品 / 新功能首次曝光** → 开 P1、P3、P4。纯短期实验可跳过 P2。
- **成熟产品增量** → 开 P1、P3。没有新用户路径可跳过 P4。
- **内部工具** → 开 P1、P3。P4 常常可跳过。
- **营销向改版** → P3 必开。看噪音和首次路径决定 P1/P4。
- **信任敏感** → P2、P3 必开，不要跳过。

把「启用 / 跳过 / 为什么」用两三句话写清。跳过的项，事后不要假装已经满足。

## 怎么评

对每个启用的方法，做 pass / fail，或 1–5 分。分数是辅助，重点是证据和改法。

**P1 少即是多**  
主路径上有多少概念、文案、步骤、选项？删掉会不会丢能力？概念堆叠、理解成本高 → fail。

**P2 长期信任**  
有没有复利（留存、信任、数据飞轮）？还是一次性噱头、透支信任？透支 → fail。

**P3 控制预期**  
承诺能不能兑现、能不能验证？空叙事、过度承诺 → fail。

**P4 叙事 / onboarding**  
短路径里，用户能不能感到被理解？价值、场景、下一步说清了吗？叙事和产品脱节 → fail。

任一启用项 fail 或 ≤2 分：给出具体改动，不要直接批准体验定稿。  
启用项都过关：可以进入规格或实现细化。

## 输出

短评即可，例如：

```
场景：……
启用：P1 P3 P4｜跳过：P2（短期实验）
发现：
- P1 fail：主路径有 3 个可删概念 → 建议删 X、合并 Y
- P3 pass：承诺与能力对齐
- P4 fail：首次屏没说清「为谁解决什么」→ 建议改文案为……
总判：需改｜优先改这 2–3 件事
```

不要搞成仪式性记分卡。分数没有改法，就没有用。

## 完成时

- 启用和跳过写清楚了
- 启用项有证据
- fail / 低分项有可执行改动

## 何时停

- 原则未过 → 退回 product-design-principles
- 场景和规模都说不清 → 先补上下文，再评
