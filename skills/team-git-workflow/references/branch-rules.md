# 分支命名与生命周期

创建、切换、重命名或删除分支之前阅读本文件。本文件是 `team-git-workflow` 的分支规则。入口与决策顺序在 `skills/team-git-workflow/SKILL.md`。

`scripts/validate-branch.sh` 只检查名字是否合法。名字合法，不表示允许新建侧分支。能否新建由下面的模式决定。

## 指定工作分支

日常改动留在仓库的指定工作分支。

认定顺序：

1. 用户在本轮点名、且允许在其上工作的分支。
2. 仓库写明的指定工作分支。远程 URL 或仓库名包含 `Izelzzz/izel-skill` 时，指定工作分支是 `feature/global`。
3. 以上都无法认定时，询问用户。不要把 `main` 或 `master` 当作默认工作分支。不要把 `feature/global` 套用到其他仓库。

共享分支指其他人可能基于它工作的分支，包括指定工作分支、`main`、`master`，以及用户称为共享的分支。向共享分支推送，须另有直推授权，见 SKILL.md 标准流程第 4 步。

## 两种模式

### 工作分支模式

同时满足下列条件时使用：

- 用户没有要求新建分支。
- 用户没有要求开 PR，也没有要求合入受保护分支。
- 用户没有说不要碰当前这条线。

做法：在指定工作分支上修改并提交。需要推送时，仅在直推授权覆盖该分支时推送。不要 `checkout -b`，不要 `switch -c`，不要创建带 `cursor/` 前缀的分支。

当前分支已经是指定工作分支时，留在该分支上。当前分支不是指定工作分支，且工作区没有用户未提交改动时，切换到指定工作分支再改文件。工作区有用户未提交改动时，先按 `safety-rules.md` 停下来。

### 侧分支模式

仅当用户明确要求新分支、要求开 PR，或明确说不要碰当前线时使用。

做法：

1. 从指定工作分支的当前最新提交拉出侧分支。命名符合下一节。
2. 在侧分支上提交。
3. 用户要的是 PR 或合入受保护分支时，按 `pr-rules.md` 开 PR。
4. 合入完成，或用户确认该分支不再使用后，删除本地分支与远程分支。

侧分支是短生命周期分支。任务结束时，远程上不得残留该分支。

## 命名

分支名只使用小写字母、数字、连字符 `-` 与斜杠 `/`。

下列名称合法：

- 本仓库指定工作分支：`feature/global`。
- 侧分支：`<类型>/<简述>`。类型只能是 `feature`、`fix`、`chore`、`docs`、`refactor`、`test`。简述由小写字母、数字与 `-` 组成，可以再含一层 `/`。

合法示例：`feature/global`、`fix/commit-message`、`docs/readme-skills`。

下列名称不合法：

- 空名、含空格、含大写字母、含下划线。
- `cursor/` 前缀。工具常默认使用此前缀；本仓库不把它当作分支名。
- 整名只有 `update` 或 `fix`。
- 游离 HEAD。`HEAD` 不能当作分支名。

`main` 与 `master` 是受保护主干。它们不是新的工作分支名。用户未点名时，不要检出后在其上提交，不要向它们直推。`validate-branch.sh` 对这两个名字返回退出码 2。

## 生命周期

| 事件 | 动作 |
|------|------|
| 开始一项用户没要求分叉的任务 | 确认当前分支就是指定工作分支。不是则切过去。存在未提交的用户改动时，按 `safety-rules.md` 停下来。 |
| 用户要求侧分支或 PR | 创建符合命名的侧分支，记下全名。 |
| 侧分支上的 PR 已合入，或用户说可以删 | 删除本地与远程该分支。 |
| 发现未经请求的 `cursor/…` 分支 | 把属于本次任务的提交移到指定工作分支，然后删除该 `cursor/…` 分支的本地与远程引用。不要开 PR。 |

删除远程分支：

```bash
git push origin --delete <侧分支名>
git branch -d <侧分支名>
```

删除的目标必须是本次创建的侧分支。不得对指定工作分支、`main`、`master` 执行删除。

把提交从错误侧分支移回指定工作分支时，在指定工作分支上 cherry-pick 属于本次任务的提交。发生冲突则按 `safety-rules.md` 停止。不要为了移动提交而 `reset --hard`，不要开 PR。

## 校验脚本

脚本可选。未接入 hook 或 CI 时，创建或切换分支之前仍按本节命名。

```bash
skills/team-git-workflow/scripts/validate-branch.sh
skills/team-git-workflow/scripts/validate-branch.sh feature/global
```

省略参数时检查当前分支。也可传入分支名。接受 `refs/heads/<名>` 前缀，检查时去掉该前缀。

退出码：

| 退出码 | 含义 |
|--------|------|
| 0 | 名称可作为工作分支或侧分支 |
| 1 | 命名不合法，或无法确定当前分支 |
| 2 | `main` 或 `master` |

脚本通过只说明名字合法。工作分支模式之下，不要因为名字能通过脚本就去创建侧分支。

## 示例

**留在工作分支。** 用户要求修改本仓库的 skill，并授权直推 `feature/global`、不要 PR。当前分支已是 `feature/global`。继续在该分支提交并推送。

**必须分叉。** 用户说「开一个 PR 合入 main」。从 `feature/global` 拉出与主题相符的侧分支，例如 `docs/git-workflow`，在其上提交并开 PR。合入后删除 `docs/git-workflow` 的本地与远程引用。

**错误侧分支。** 当前在 `cursor/add-skill-ede9`，用户要求的是直推 `feature/global`。把本次提交 cherry-pick 到 `feature/global`，在直推授权下推送到 `feature/global`，再删除本地与远程的 `cursor/add-skill-ede9`。不开 PR。
