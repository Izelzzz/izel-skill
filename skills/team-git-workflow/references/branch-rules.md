# 分支命名、创建与生命周期

创建、切换、命名或删除分支之前阅读本文件。决策顺序在 `SKILL.md`。仓库自己的分支约定优先于这里的默认格式。

`scripts/validate-branch.sh` 只判断名字是否符合下面的默认格式。退出码 0 表示符合默认格式。退出码 1 表示不符合，或无法确定当前分支。仓库已经规定的分支名（包括受保护基线，以及 Izelzzz/izel-skill 的 `feature/global`）由优先级第 3 级决定能不能用，不由这个脚本授予或取消。

## 命名

仓库定义了分支前缀或格式时，使用仓库的格式。

仓库没有定义时，使用：

```text
<type>/<short-description>
```

默认类型只有：

| 类型 | 用于 |
|------|------|
| `feat/` | 新能力 |
| `fix/` | 缺陷修复 |
| `refactor/` | 不改变外部行为的结构调整 |
| `docs/` | 文档 |
| `test/` | 测试 |
| `chore/` | 杂项维护 |
| `hotfix/` | 需要尽快落地的生产修复 |

示例：`feat/add-review-summary`、`fix/oauth-token-refresh`、`refactor/git-command-runner`、`docs/update-agent-guide`。

名称要求：

- 小写英文，单词之间用连字符 `-`。
- 短，并且具体到这次任务或改动。
- 不要空格，不要下划线，不要其他标点。
- 不要放入姓名、邮箱、客户名或其他个人敏感信息。
- 工单号只有仓库要求时才放进名字，并按仓库要求的写法放置。

`feature/`、`cursor/` 不是默认类型。`main`、`master` 以及其他基线名也不是任务分支名。它们可以是仓库里已经存在的分支；能不能在上面提交，由下一节和 `SKILL.md` 第 2 节决定。

## 创建与切换

不要假定当前分支可以安全修改。先用 `git status --short --branch` 和 `git branch --show-current` 看清自己站在哪里，工作区里有什么。

不要从猜测的基线创建分支。建分支、合并、变基或开 PR 之前，确认这次任务的基线，以及 PR 或合并的目标。基线不清楚时询问，不要默认选 `main`。

只有下面两件同时成立时，才复用已有分支：这是同一项任务；复用不会把无关改动混进这次提交。别人的分支、上一项任务的分支、来历不明的 `cursor/*` 分支，都不要顺手拿来继续提交。

切换分支会覆盖或丢失本地改动时，不要切换。先按 `safety-rules.md` 处理未提交的工作。不要用 `reset --hard` 或 `clean -fd` 给切换清路。

没有明确授权，并且仓库政策也不允许时，不要把任务改动直接提交到受保护或共享的基线分支。共享分支指其他人可能基于它工作的分支，包括发布分支、仓库指定的默认分支，以及用户称为共享的分支。

## 生命周期

任务完成后不要自动删除分支。分支留着，评审和回溯才找得到对应提交。

只在下面两种情况删除：

- 用户明确要求删除这条分支。
- 一项已经成立的授权清理政策适用。授权要能对应到具体仓库和具体分支范围。

删除前：

1. 核对全名，确认要删的就是这一条，而不是同名的另一条、基线分支或别人的分支。
2. 查看它是否还有未合并、且仍然有价值的提交。有，而且这些提交不属于用户授权你处理的范围时，停下来询问。
3. 使用普通删除。不要为了删分支而 force-push。

```bash
git push origin --delete <分支名>
git branch -d <分支名>
```

远程没有这条约分支时，只删除本地引用。`git branch -d` 因未合并而拒绝时，不要改成 `-D`，除非用户已经授权丢弃那些提交。

## 本仓库的指定工作分支

仅当远程 URL 或仓库名是 Izelzzz/izel-skill 时：

- 指定工作分支是已经存在的 `feature/global`。用户没有点名别的分支时，在这条分支上工作。
- 这个名字不符合默认的 `<type>/<desc>`。不要因此把它重命名为 `feat/global`。`validate-branch.sh` 对它返回 1，只表示它不是默认任务分支格式。
- 在这条共享分支上提交，是该仓库政策所允许的。推送到这条分支仍然要有 `SKILL.md` 第 2 节里的直推授权。
- 用户另外要求新分支或 PR 时，从 `feature/global` 拉出符合默认格式的任务分支。任务结束后不要自动删除那条任务分支，除非用户明确要求，或适用该仓库对 `cursor/*` 残留的清理政策。

其他仓库不要把 `feature/global` 当作自己的工作分支。

## 脚本

在使用默认格式创建任务分支之前可以运行：

```bash
scripts/validate-branch.sh
scripts/validate-branch.sh fix/oauth-token-refresh
```

省略参数时检查当前分支。传入 `refs/heads/<名>` 时，检查去掉前缀后的名字。

脚本不决定能不能创建分支，也不识别仓库特例。创建之前仍然要完成本文件的基线确认。
