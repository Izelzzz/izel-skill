# 产品调研规范

## 何时使用

在以下情况 MUST 使用本 skill：

- 进入新产品或新方向前的行业摸底
- 竞品分析（直接 + 间接）
- 需要行业研究报告或行业技术文档摘要

开始时宣布：正在使用 product-research 执行调研。

## 调研范围

本 skill 覆盖三类材料：

1. 行业研究报告
2. 行业技术文档
3. 竞品分析

## Step 1 — 写调研计划

先填计划，再搜集。不要边搜边定问题。

```
【调研计划】
主题：
决策问题（本调研要回答什么）：
范围（含 / 不含）：
时间窗（材料时效）：
直接竞品候选：
间接竞品候选：
负责人 / 截止时间：
交付物：总结报告（趋势 / 机会点 / 差异化方向）
```

## Step 2 — 源质量门禁

行业报告与技术文档 MUST 满足：

| 门禁 | 要求 |
|------|------|
| 公信力 | 第三方研究机构，或行业头部厂商 |
| 时效 | 落在计划时间窗内；过期材料须标注并降权 |
| 权威 | 可追溯作者/机构 |
| 客观 | 区分事实与厂商宣传 |
| 真实 | 可核对原文链接或出处 |

规则：

- MUST NOT 把匿名转述、无出处截图当主证据。
- 厂商材料可用，但 MUST 标为「一级相关方」，并与第三方交叉验证。
- 每条关键主张 MUST 附来源。

源记录模板：

```
标题 | 机构 | 日期 | URL | 类型(报告/技术文档/blog/changelog/试用) | 可信度(高/中/低) | 备注
```

## Step 3 — 竞品收集

竞品类型：

- **直接竞品**：同一主问题、重叠用户
- **间接竞品**：相邻方案、可替代路径

主来源（按优先级）：

1. 产品 blog
2. 产品 changelog
3. 直接上手试用

次要来源：文档、定价页、公开案例。次要来源 MUST NOT 单独支撑关键结论。

## Step 4 — 填竞品矩阵

每个竞品 MUST 尽量覆盖以下维度：

| 维度 | 填写要点 |
|------|----------|
| 产品名称 | 官方名 |
| 目标用户/客户群 | 角色与场景 |
| 用户/客户规模 | 有证据则写；无则标未知 |
| 产品定位 | 一句话 |
| 功能点 | 与决策相关的能力列表 |
| 功能架构 | 模块如何组织（能画则画） |
| 数据结构 | 核心对象与关系（公开可知部分） |
| 用户体验 | 主路径与明显摩擦 |
| 商业模式 | 收费与增长方式 |

矩阵最小行数：

- 直接竞品 ≥ 2（若市场不足 2，写明并分析全部已知）
- 间接竞品 ≥ 1（若无，写明「未发现」）

## Step 5 — 写总结报告

报告 MUST 含三块，且每块有证据指针（回链到源表或矩阵单元格）：

```
# 调研总结：<主题>

## 1. 行业趋势
- 趋势陈述 + 来源
- …

## 2. 可能的机会点
- 机会 + 依据 + 风险
- …

## 3. 差异化方向
- 方向 + 对谁有利 + 不做会怎样
- …

## 附录
- 源列表
- 竞品矩阵
- 未验证假设
```

## Step 6 — Done when（完成闸门）

全部满足才可声称调研完成：

- [ ] 调研计划已写且决策问题清晰
- [ ] 关键源通过质量门禁，或已降权并说明
- [ ] 直接/间接竞品已区分
- [ ] 竞品矩阵维度已填（未知已标明）
- [ ] 主来源含 blog / changelog / 试用中至少一类实质材料
- [ ] 总结报告含：行业趋势、机会点、差异化方向
- [ ] 未验证假设单独列出

未满足 → MUST NOT 说「调研完成」。只报告完成度与缺口。

## 停止条件

- 无法取得任何可信源 → 输出阻塞清单，停止下结论
- 用户只要「快速印象」→ 可出简报，但 MUST 标注「非正式调研，未过完成闸门」
